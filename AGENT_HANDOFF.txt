     redisConnected=false

   This is okay. Redis is not required for the current deployment because
   backend/services/jobManager.js falls back to backend/services/localJobs.js.
   The frontend error message blaming Redis was misleading.

3. Backend system health after fixes:

     redisConnected: false
     queueMode: local
     pythonServiceReachable: true

4. Cookie diagnostics after fixes:

     GET /api/system/cookies -> 200
     envExists: true
     cookiesPath: /tmp/youtube-cookies.txt
     fileExists: true

5. Current real blocker is YouTube authentication, not Redis or backend uptime.
   Render logs now show:

     WARNING: [youtube] The provided YouTube account cookies are no longer valid.
     They have likely been rotated in the browser as a security measure.

     ERROR: [youtube] <video_id>: Sign in to confirm you're not a bot.

   This means Render's YOUTUBE_COOKIES value is expired/rotated.
   The app cannot reliably stream/download YouTube audio until fresh valid
   Netscape-format YouTube cookies are placed in Render's backend env var.

Important safety notes
----------------------
The issue is not currently Redis.

for the current local-mode deployment.

Do not try to bypass YouTube bot protection using shady proxy scraping or
uncookied automation. The correct fix is fresh valid user-provided cookies or
moving to a legitimate audio source/API.
